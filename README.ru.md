# claude-cache-keeper

Чтобы долгоживущие сессии [Claude Code](https://claude.com/claude-code) дёшево просыпались.

[English](README.md)

## Проблема

Если держать открытыми несколько сессий Claude Code сутками (команда агентов в
tmux, вкладки проектов), основная часть счёта уходит не на работу, а на
**пробуждения**.

- Кэш промптов живёт **1 час** после последнего запроса к модели.
- Пока он жив, контекст читается из кэша за малую долю цены.
- После часа простоя кэша нет. Следующее сообщение — твоё, соседнего агента,
  плановый пинг — пишет в кэш **весь контекст** заново по полной цене. Сессия на
  400k токенов платит за 400k, чтобы ответить «ок».
- Пинговать сессию, «чтобы кэш не остыл», — антипаттерн: платишь каждый раз и
  покупаешь ещё час. Открытая простаивающая сессия ничего не стоит.

Решение: сделать `/compact` большой простаивающей сессии за несколько минут
**до** истечения кэша. Сжатие ещё читает контекст из кэша (дёшево) и оставляет
короткую сводку — следующее пробуждение стоит копейки.

## Что внутри

| часть | что делает | нужно |
|---|---|---|
| `plugins/cache-keeper/` — **мод cache-keeper** | Каждая сессия следит за своим простоем. На 50-й минуте при контексте больше 60k сжимает себя сама (`$.session.compact()`). `/cache` — сколько осталось кэшу. Если пишешь в сессию, у которой кэш уже остыл, сначала спросит: сжать и отправить, отправить как есть или оставить черновик. | Claude Code с модами (проверено на 2.1.296) |
| `bin/agents` | `agents status` — все живые сессии на машине: статус, простой, кэш, контекст, модель, окно tmux. `agents compact-idle` — запасное сжатие для сессий, запущенных без мода. | Python 3, tmux для сжатия |
| `systemd/` | `agents compact-idle` раз в 2 мин (окно 53–59 мин). | user-сессия systemd |
| `statusline/` | Таймер `💾 42m` в строке состояния; жёлтый меньше 10 мин, серый — истёк. | `jq` |
| `plugins/push-guard/` — **мод push-guard** | Не даёт сделать `git push` в ветку, чей PR уже влит (коммиты не дойдут до базовой ветки), и спрашивает **тебя** в диалоге: пушит только после твоего «да», иначе агенту велено завести новую ветку. Обхода, который модель могла бы вписать в команду сама, нет. Нет ответа за `PUSH_GUARD_ASK_MIN` минут (10) — отказ, так что агент без присмотра не зависнет на вопросе; уведомление на рабочем столе скажет, что агент ждёт. Без `gh` и вне GitHub пропускает. | `gh` с логином |
| `plugins/agents-panel/` — **мод agents-panel** | Одна строка над полем ввода: кто сейчас работает, сколько сессий простаивают и у скольких из них остыл кэш (💤), последнее сообщение между сессиями и сколько пунктов чек-листа ждут тебя. `/team` открывает и закрывает панель: каждая живая сессия — пиксельная девочка или мальчик (`people.conf`) в цвете модели (Haiku синий, Sonnet янтарный, Opus фиолетовый, Fable зелёный), что каждый делает, последние сообщения; клик по имени (или 1–9) — переход в её окно tmux. `/checklist` — вкладка только для чтения: открытые пункты по проектам, твои сверху. | `bin/agents` в `PATH` |

Слои пересекаются нарочно: мод срабатывает первым; таймер подбирает сессии,
запущенные до установки мода; строка состояния показывает всё человеку.

## Установка

```bash
git clone https://github.com/nazmang/claude-cache-keeper ~/src/claude-cache-keeper
~/src/claude-cache-keeper/install.sh
```

Установщик выпускает релиз (`release.sh`), делает из него ссылки `agents` и
`cache-segment.sh` в `~/.local/bin` и включает таймер systemd. `settings.json`
он **не** трогает — добавь сам (пример в [README.md](README.md#install)):
`env.CLAUDE_CODE_PLUGIN_DIRS` с путями к
`~/.local/share/claude-cache-keeper/current/plugins/<мод>` через двоеточие
(запятая не работает; из окружения shell переменная не подхватилась — только из
`settings.json`) и `statusLine.refreshInterval: 30` — без него строка в простое
не перерисовывается.

Попробовать мод в одной сессии: `claude --plugin-dir ~/src/claude-cache-keeper/plugins/cache-keeper`.

> **Уже запущенные сессии мод не подхватят**, даже по `/reload-plugins`:
> список каталогов плагинов читается при старте процесса. Перезапусти их
> (сначала `/compact`!) или положись на запасной путь через systemd.

## Работа

- `agents status` — таблица сессий; `context` = `compact` — после сжатия ничего не добавилось.
- `agents compact <имя> --wait` — сжать сейчас и дождаться нового `compact_boundary` в транскрипте.
- `agents up|down <проект> [имена…]` — поднять/закрыть сессии проекта в tmux.
  - Простые сессии — в `~/.config/agents/sessions.conf`
    (`проект | имя | каталог | модель | id сессии [| доп. аргументы]`): окно на
    строку, `claude -n <имя> --resume <id>`; без id — новая сессия, id допишется
    сам. Уже запущенные (в tmux или во вкладке терминала) не трогает. `down`
    сначала сжимает, потом `/exit`; занятые и с черновиком в поле ввода пропускает.
  - Команды со своими скриптами — в `~/.config/agents/projects.conf`
    (`проект | каталог | команда up | команда down`).
  - Перенос вкладки в tmux: во вкладке `/compact`, `/exit`, затем `agents up <проект>`.
- `agents down <проект> --no-compact` — закрыть без сжатия: если кэш уже остыл,
  сжатие само перечитает весь контекст по полной цене. `agents up <проект>
  --fresh` — новая сессия вместо сохранённого id (например, ночной перезапуск
  дежурного с чистого листа). 6-й столбец `sessions.conf` — доп. аргументы
  `claude` для этой сессии.
- Сессия, у которой работает только фоновый shell или монитор, видна как
  `shell`; она считается свободной, и `down` сам отвечает на диалог
  «Background work is running».
- `agents messages [--hours H]` — сообщения между сессиями (SendMessage);
  ❄ — сообщение разбудило получателя с остывшим кэшем.
- `/cache` внутри сессии.
- Лог: `~/.local/state/agents/compact-idle.log`.

### Релизы: не грузить моды из рабочей папки

Запущенные сессии перечитывают мод при каждом изменении его файлов. Если
настройки смотрят в рабочую копию, каждая недописанная правка сразу попадает
во всех агентов. Поэтому:

- `./release.sh` — только закоммиченное, только после `validate` и `test` всех
  плагинов, копия `bin/`, `plugins/` и `statusline/` в
  `~/.local/share/claude-cache-keeper/releases/<sha>`, атомарное переключение
  `current`; `--list`, `--rollback <sha>`.
- Отказывает и при неотслеживаемых файлах: файла, который есть только у тебя,
  не будет ни в одном другом клоне (так однажды случилось с самим `release.sh`).
- Настройки, `agents` и таймер смотрят в `current`, никогда не в репозиторий.
- Разработка — в отдельном worktree (`git worktree add ../claude-cache-keeper-dev -b dev`),
  слить в `main`, потом выпустить.

### Данные agents-panel

У мода нет доступа к файлам, поэтому он спрашивает `agents status --json
--max-age 5`; ответ кэшируется, и все сессии вместе пересчитывают его не чаще
раза в 5 с.

- `~/.config/agents/people.conf` — `имя сессии | отображаемое имя | f|m|-|x` (см. `examples/`).
- Чек-лист: по JSON на пункт в `~/.local/state/agents/checklist/items/`
  (`{id, data: {project, title, who, status}}`) — например, выгрузка базы
  артефакта Claude. Открытые (`status: todo`), у которых `who` из `OWNER_WHO`
  (по умолчанию `owner,together,you` и русские близнецы), считаются ждущими тебя.

### Окно-табло

Запусти одну дешёвую сессию (любая модель; запросов она не делает) с
`AGENTS_PANEL_OPEN=1` в `env` своего файла настроек
(`claude --settings ~/.config/agents/panel-settings.json`) — она сама откроет
`/team` и `/checklist`. Пометь её `x` в `people.conf`, чтобы не попадала в
список агентов. Сбоку от поля ввода панели встают только в достаточно широком
терминале, иначе — над ним. Пиксельные фигурки (`Raster`) рисует только
терминальный интерфейс.

Пороги и переменные — в таблице «Tuning» в [README.md](README.md#tuning).

Язык: всё, что читает человек (строка статуса, `agents`, моды), выбирается по
локали. Задан `AGENTS_LANG` (`ru` или `en`) — берётся он; иначе первое непустое
из `LC_ALL`, `LC_MESSAGES`, `LANG`: начинается с `ru` — по-русски, иначе
по-английски. `agents status --json` и текст отказов, который получает модель,
не переводятся.

## Безопасность

- `$.session.compact()` отказывает во время хода — мод повторит на следующем
  тике. Недописанный текст в поле ввода сохраняется.
- `agents compact-idle` пишет `/compact` в окно tmux, только если сессия `idle`
  **и** поле ввода пустое. Сессии вне tmux не трогает.
- Ходы субагентов не сбрасывают отсчёт — у них свой кэш.
- Вопрос про остывший кэш останавливает только то, что набрал человек
  (терминал или мост с телефона); сообщения других сессий, уведомления задач и
  плановые триггеры проходят как есть. Сжатие нельзя запустить внутри хука
  отправки, поэтому «сжать и отправить» снимает сообщение, сжимает, а Enter
  жмёшь ещё раз.
- Пороги `CACHE_KEEPER_*` читаются из `env` в `settings.json`, не из окружения shell.

## Грабли, на которые уже наступили

- Конец `/compact` нельзя определять по экрану: там может висеть старая
  надпись `Compacted`. `agents compact --wait` смотрит транскрипт.
- Интервал таймера должен быть заметно меньше окна сжатия. При таймере
  «5 минут» (на деле ~5,5) и окне в 4 минуты сессия на 191k проскочила.
- Перед перезапуском с `--resume` — сначала `/compact`, иначе весь несжатый
  хвост снова уйдёт в кэш.
- Последний `usage` в транскрипте завышает контекст, если после него было сжатие.
- Запущенные сессии перечитывают мод при каждом сохранении — отсюда `release.sh`.
- `$.session.compact()` нельзя звать из хука `prompt.submit`: он держит ход.
- dev- и release-копии `agents` пишут один кэш `status.json` — проверять мод
  после выпуска, а не из dev.
