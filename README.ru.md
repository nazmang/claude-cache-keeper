# claude-cache-keeper

**Чтобы долгоживущие сессии [Claude Code](https://claude.com/claude-code) дёшево просыпались.**

Мод для Claude Code: сжимает простаивающую сессию за несколько минут до того,
как истечёт её кэш промпта. Следующее сообщение не платит за то, чтобы заново
записать весь контекст.

[English](README.md)

- **−89 %** токенов, записанных в кэш на одно холодное пробуждение (536k → 61k)
- **−63 %** стоимости запроса на машине с ~10 долгоживущими сессиями
- Ни демона, ни таймера, ни tmux: каждая сессия следит за собой сама

## Проблема

Если держать открытыми несколько сессий Claude Code сутками (команда агентов в
tmux, вкладки проектов), основная часть счёта уходит не на работу, а на
пробуждения.

- Кэш промптов живёт 1 час после последнего запроса к модели.
- Пока он жив, контекст читается из кэша за малую долю цены.
- После часа простоя кэша нет. Следующее сообщение (твоё, соседнего агента,
  плановый пинг) пишет в кэш весь контекст заново по полной цене. Сессия на
  400k токенов платит за 400k, чтобы ответить «ок».
- Пинговать сессию, «чтобы кэш не остыл», бесполезно: платишь каждый раз и
  покупаешь ещё час. Открытая простаивающая сессия ничего не стоит.

## Как это работает

```
 последний ответ      50-я минута                   60-я минута
     │                    │                             │
─────●────────────────────●─────────────────────────────┼─────────────▶ время
     кэш тёплый           /compact, пока кэш ещё        кэш истёк:
                          тёплый (дешёвое чтение,       пробуждение пишет
                          остаётся короткая сводка)     ~60k вместо ~500k
```

1. Каждая сессия считает собственный простой.
2. На 50-й минуте, если контекст больше 60k токенов, сессия сжимает себя сама
   (`$.session.compact()`). Сжатие ещё читает контекст из тёплого кэша и
   оставляет короткую сводку.
3. Если пишешь в сессию, у которой кэш уже остыл, мод сначала спросит:
   **сжать и отправить**, **отправить как есть** или **не отправлять**.
4. `/cache` показывает, сколько осталось кэшу и что мод собирается делать.
5. Необязательный сегмент строки состояния показывает таймер `💾 42м`.

## Быстрый старт

```bash
git clone https://github.com/nazmang/claude-cache-keeper ~/src/claude-cache-keeper
~/src/claude-cache-keeper/install.sh
```

Потом добавь в `~/.claude/settings.json` (замени `/home/you`):

```jsonc
{
  // несколько плагинов: через двоеточие (запятая не работает)
  "env": { "CLAUDE_CODE_PLUGIN_DIRS": "/home/you/.local/share/claude-cache-keeper/current/plugins/cache-keeper" },
  "statusLine": {
    "type": "command",
    "command": "/home/you/.local/share/claude-cache-keeper/current/statusline/example-statusline.sh",
    "refreshInterval": 30
  }
}
```

Перезапусти сессии (сначала сделай в них `/compact`). Всё.

Попробовать в одной сессии:

```bash
claude --plugin-dir ~/src/claude-cache-keeper/plugins/cache-keeper
```

> [!IMPORTANT]
> - **Уже запущенные сессии мод не подхватят**, даже по `/reload-plugins`:
>   список каталогов плагинов читается при старте процесса. Перезапусти их.
> - Переменную задавай в `settings.json`, не в shell: из окружения она не
>   подхватилась (Claude Code 2.1.296).
> - Без `"refreshInterval": 30` строка состояния в простое не перерисовывается,
>   и таймер замирает.

### Что нужно

- Claude Code с поддержкой модов (проверено на 2.1.296 и 2.1.318)
- Linux: скрипты используют GNU `date -d`, `tac` и `mv -T`
- `jq` для строки состояния

## Использование

- Внутри сессии: `/cache` →
  `кэш: осталось ~40 мин; контекст 120k; сожму через 30 мин простоя`.
- Работает ли мод? Своего лога у него нет. Ищи `compact_boundary` в
  транскрипте сессии минут через 50 после её последнего ответа или запусти `/cache`.
- Уже есть своя строка состояния? Пропусти её вход через `cache-segment.sh`:

  ```bash
  input=$(cat)
  CACHE=$(echo "$input" | ~/.local/bin/cache-segment.sh)
  echo -e "... $CACHE"
  ```

  Зелёный, жёлтый меньше 10 минут, серый, когда кэш истёк.
- Таблица всех живых сессий с простоем, остатком кэша и контекстом:
  `agents status` из [claude-agents-kit](https://github.com/nazmang/claude-agents-kit).

### Настройки

| переменная | по умолчанию | что делает |
|---|---|---|
| `CACHE_KEEPER_AT_MIN` | `50` | сжимать после N минут простоя |
| `CACHE_KEEPER_MIN_TOKENS` | `60000` | контекст меньше не сжимать: не окупится |
| `CACHE_KEEPER_CACHE_MIN` | `60` | время жизни кэша, минуты |
| `CACHE_KEEPER_TICK_MS` | `60000` | как часто мод проверяет |
| `CACHE_TTL_MIN` | `60` | время жизни кэша для строки состояния |
| `AGENTS_LANG` | по локали | `ru` или `en` для всего, что читает человек |

Если `AGENTS_LANG` не задан, решает первое непустое из `LC_ALL`, `LC_MESSAGES`,
`LANG`: начинается с `ru` — по-русски, иначе по-английски. Текст, который
получает модель, не переводится. Переменные `CACHE_KEEPER_*` читаются из `env`
в `settings.json`, не из окружения shell.

Если у тебя кэш на 5 минут (например, при перерасходе лимита), эти настройки не
помогут: кэш истекает задолго до 50-й минуты.

## Окупается ли

Замер на одной машине, ~10 долгоживущих сессий (команда агентов в tmux и
вкладки проектов), только по полям `usage` в транскриптах. Стоимость — в
эквивалентах входного токена (запись в кэш на час 2.0, чтение из кэша 0.1,
вход 1.0, выход 5.0), чтобы складывать модели с разной ценой.

| в среднем за день | до (9 дней) | после (6 дней) |
|---|---|---|
| запросов | 1041 | 1577 |
| холодных пробуждений (простой > 60 мин) | 11 | 21 |
| записано в кэш **на одно холодное пробуждение** | 536k | **61k** (−89 %) |
| запись в кэш при холодных пробуждениях | 5.9M | 1.3M (−78 %) |
| стоимость одного запроса | 67k | **25k** (−63 %) |

- Чистый эффект — строка «на одно пробуждение»: от объёма работы она почти не
  зависит. В падении стоимости запроса есть и другие перемены в том, как
  работали сессии.
- Сжатие не бесплатно: оно читает контекст из кэша и пишет сводку (~5k токенов
  выхода). За 6 дней 158 сжатий стоили около 6.5M эквивалентов и сберегли около
  26M на последующих пробуждениях — чистыми ≈ 3M в день.
- 8 из 158 сессий больше не проснулись — их сжатие ушло впустую. По той же
  причине контекст меньше `CACHE_KEEPER_MIN_TOKENS` не сжимается.

Замерить у себя: среднее `cache_creation_input_tokens` первого запроса после
часа тишины — до установки и после.

## Безопасность

- `$.session.compact()` отказывает во время хода — мод повторит на следующем
  тике. Недописанный текст в поле ввода сохраняется.
- Ходы субагентов не сбрасывают отсчёт — у них свой кэш.
- Вопрос про остывший кэш останавливает только то, что набрал человек
  (терминал или мост с телефона). Сообщения других сессий, уведомления задач и
  плановые триггеры проходят как есть.
- Сжатие нельзя запустить внутри хука отправки, поэтому «сжать и отправить»
  снимает сообщение (оно возвращается в поле ввода), сжимает, а Enter жмёшь
  ещё раз.

## Разработка

### Релизы: не грузить моды из рабочей папки

Запущенные сессии перечитывают мод при каждом изменении его файлов. Если
настройки смотрят в рабочую копию, каждая недописанная правка сразу попадает
во все сессии. Поэтому:

- `./release.sh` отказывает при незакоммиченных и неотслеживаемых файлах,
  запускает `claude plugin validate` и `claude plugin test` для всех плагинов,
  копирует закоммиченные `plugins/` и `statusline/` в
  `~/.local/share/claude-cache-keeper/releases/<sha>` и атомарно переключает
  `current`. Хранятся последние 5 релизов.
- `./release.sh --list` — список релизов, `./release.sh --rollback <sha>` — откат.
- Настройки и `~/.local/bin/cache-segment.sh` смотрят в
  `~/.local/share/claude-cache-keeper/current/...`, никогда не в репозиторий.
- Разработка — в отдельном worktree (`git worktree add ../claude-cache-keeper-dev -b dev`),
  слить в `main`, потом выпустить.

### Тесты

```bash
claude --plugin-dir plugins/cache-keeper   # один раз, интерактивно: генерирует .claude-plugin/types
claude plugin validate plugins/cache-keeper && claude plugin test plugins/cache-keeper
```

### Грабли, на которые уже наступили

- Конец `/compact` нельзя определять по экрану: там может висеть старая
  надпись `Compacted`. Смотреть надо новый `compact_boundary` в транскрипте.
- Сжатие изнутри сессии надёжнее, чем снаружи: внешнему таймеру приходилось
  угадывать по экрану, пустое ли поле ввода и не занята ли сессия. До октября
  2026 здесь был такой таймер systemd на всякий случай; с модом он сработал
  4 раза в первый день и ни разу за неделю после, поэтому его убрали.
- Перед перезапуском с `--resume` — сначала `/compact`, иначе весь несжатый
  хвост снова уйдёт в кэш.
- Последний `usage` в транскрипте завышает контекст, если после него было сжатие.
- `$.session.compact()` нельзя звать из хука `prompt.submit`: он держит ход.

## Удаление

```bash
rm ~/.local/bin/cache-segment.sh
```

Убери `CLAUDE_CODE_PLUGIN_DIRS` и строку состояния из `settings.json` и
перезапусти сессии. После этого можно удалить `~/.local/share/claude-cache-keeper/`.
