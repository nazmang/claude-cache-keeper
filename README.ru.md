# claude-cache-keeper

Чтобы долгоживущие сессии [Claude Code](https://claude.com/claude-code) дёшево просыпались.

[English](README.md)

> `agents` и моды agents-panel и push-guard раньше жили здесь. Они переехали в
> [claude-agents-kit](https://github.com/nazmang/claude-agents-kit).

## Проблема

Если держать открытыми несколько сессий Claude Code сутками (команда агентов в
tmux, вкладки проектов), основная часть счёта уходит не на работу, а на
пробуждения.

- Кэш промптов живёт 1 час после последнего запроса к модели.
- Пока он жив, контекст читается из кэша за малую долю цены.
- После часа простоя кэша нет. Следующее сообщение — твоё, соседнего агента,
  плановый пинг — пишет в кэш весь контекст заново по полной цене. Сессия на
  400k токенов платит за 400k, чтобы ответить «ок».
- Пинговать сессию, «чтобы кэш не остыл», — антипаттерн: платишь каждый раз и
  покупаешь ещё час. Открытая простаивающая сессия ничего не стоит.

Решение: сделать `/compact` большой простаивающей сессии за несколько минут
до истечения кэша. Сжатие ещё читает контекст из кэша (дёшево) и оставляет
короткую сводку — следующее пробуждение стоит копейки.

## Что внутри

| часть | что делает | нужно |
|---|---|---|
| `plugins/cache-keeper/` (мод) | Каждая сессия следит за своим простоем. На 50-й минуте при контексте больше 60k сжимает себя сама (`$.session.compact()`). `/cache` — сколько осталось кэшу. Если пишешь в сессию, у которой кэш уже остыл, сначала спросит: сжать и отправить, отправить как есть или оставить черновик. | Claude Code с модами (проверено на 2.1.296) |
| `statusline/` | Таймер `💾 42m` в строке состояния; жёлтый меньше 10 мин, серый — истёк. | `jq` |

Каждая сессия сжимает себя сама: ни демона, ни таймера, tmux не нужен. Сессия,
запущенная до установки мода, его не получит — перезапусти её один раз.

> До октября 2026 здесь был ещё таймер systemd, который вписывал `/compact` в
> простаивающие окна tmux на случай сессий без мода. После установки мода он
> сработал 4 раза в первый день и ни разу за неделю после, поэтому его убрали.

## Окупается ли

Замер на одной машине, ~10 долгоживущих сессий (команда агентов в tmux и
вкладки проектов), только по полям `usage` в транскриптах. Стоимость — в
эквивалентах входного токена (запись в кэш на час 2.0, чтение из кэша 0.1,
вход 1.0, выход 5.0), чтобы складывать модели с разной ценой.

| в среднем за день | до (9 дней) | после (6 дней) |
|---|---|---|
| запросов | 1041 | 1577 |
| холодных пробуждений (простой > 60 мин) | 11 | 21 |
| записано в кэш **на одно холодное пробуждение** | 536k | **61k** (−89 %) |
| запись в кэш при холодных пробуждениях | 5.9M | 1.3M (−78 %) |
| стоимость одного запроса | 67k | **25k** (−63 %) |

- Чистый эффект — строка «на одно пробуждение»: от объёма работы она почти не
  зависит. В падении стоимости запроса есть и другие перемены в том, как
  работали сессии.
- Сжатие не бесплатно: оно читает контекст из кэша и пишет сводку (~5k токенов
  выхода). За 6 дней 158 сжатий стоили около 6.5M эквивалентов и сберегли около
  26M на последующих пробуждениях — чистыми ≈ 3M в день.
- 8 из 158 сессий больше не проснулись — их сжатие ушло впустую. По той же
  причине контекст меньше `CACHE_KEEPER_MIN_TOKENS` не сжимается.

Замерить у себя: среднее `cache_creation_input_tokens` первого запроса после
часа тишины — до установки и после.

## Установка

```bash
git clone https://github.com/nazmang/claude-cache-keeper ~/src/claude-cache-keeper
~/src/claude-cache-keeper/install.sh
```

Установщик выпускает релиз (`release.sh`) и делает из него ссылку
`cache-segment.sh` в `~/.local/bin`. `settings.json` он не трогает — добавь сам (пример в [README.md](README.md#install)):
`env.CLAUDE_CODE_PLUGIN_DIRS` с путями к
`~/.local/share/claude-cache-keeper/current/plugins/cache-keeper` (несколько
каталогов — через двоеточие, запятая не работает; из окружения shell переменная не подхватилась — только из
`settings.json`) и `statusLine.refreshInterval: 30` — без него строка в простое
не перерисовывается.

Попробовать мод в одной сессии: `claude --plugin-dir ~/src/claude-cache-keeper/plugins/cache-keeper`.

> **Уже запущенные сессии мод не подхватят**, даже по `/reload-plugins`:
> список каталогов плагинов читается при старте процесса. Перезапусти их
> (сначала `/compact`!).

## Работа

- `/cache` внутри сессии — сколько осталось кэшу и когда будет сжатие.
- Работает ли мод: своего лога у него нет. Смотри `compact_boundary` в
  транскрипте сессии минут через 50 после её последнего ответа или `/cache`.
- Таблица всех живых сессий с простоем, кэшем и контекстом — `agents status`
  из [claude-agents-kit](https://github.com/nazmang/claude-agents-kit).

### Релизы: не грузить моды из рабочей папки

Запущенные сессии перечитывают мод при каждом изменении его файлов. Если
настройки смотрят в рабочую копию, каждая недописанная правка сразу попадает
во всех агентов. Поэтому:

- `./release.sh` — только закоммиченное, только после `validate` и `test` всех
  плагинов, копия `plugins/` и `statusline/` в
  `~/.local/share/claude-cache-keeper/releases/<sha>`, атомарное переключение
  `current`; `--list`, `--rollback <sha>`.
- Отказывает и при неотслеживаемых файлах: файла, который есть только у тебя,
  не будет ни в одном другом клоне (так однажды случилось с самим `release.sh`).
- Настройки и `cache-segment.sh` смотрят в `current`, никогда не в репозиторий.
- Разработка — в отдельном worktree (`git worktree add ../claude-cache-keeper-dev -b dev`),
  слить в `main`, потом выпустить.

Пороги и переменные — в таблице «Tuning» в [README.md](README.md#tuning).

Язык: всё, что читает человек (строка статуса, `/cache`, диалог), выбирается по
локали. Задан `AGENTS_LANG` (`ru` или `en`) — берётся он; иначе первое непустое
из `LC_ALL`, `LC_MESSAGES`, `LANG`: начинается с `ru` — по-русски, иначе
по-английски. Текст, который получает модель, не переводится.

## Безопасность

- `$.session.compact()` отказывает во время хода — мод повторит на следующем
  тике. Недописанный текст в поле ввода сохраняется.
- Ходы субагентов не сбрасывают отсчёт — у них свой кэш.
- Вопрос про остывший кэш останавливает только то, что набрал человек
  (терминал или мост с телефона); сообщения других сессий, уведомления задач и
  плановые триггеры проходят как есть. Сжатие нельзя запустить внутри хука
  отправки, поэтому «сжать и отправить» снимает сообщение, сжимает, а Enter
  жмёшь ещё раз.
- Пороги `CACHE_KEEPER_*` читаются из `env` в `settings.json`, не из окружения shell.

## Грабли, на которые уже наступили

- Конец `/compact` нельзя определять по экрану: там может висеть старая
  надпись `Compacted`. Смотреть надо новый `compact_boundary` в транскрипте.
- Сжатие изнутри сессии надёжнее, чем снаружи: внешнему таймеру приходилось
  угадывать по экрану, пустое ли поле ввода и не занята ли сессия.
- Перед перезапуском с `--resume` — сначала `/compact`, иначе весь несжатый
  хвост снова уйдёт в кэш.
- Последний `usage` в транскрипте завышает контекст, если после него было сжатие.
- Запущенные сессии перечитывают мод при каждом сохранении — отсюда `release.sh`.
- `$.session.compact()` нельзя звать из хука `prompt.submit`: он держит ход.

## Тесты

```bash
claude --plugin-dir plugins/cache-keeper   # один раз, интерактивно: генерирует .claude-plugin/types
claude plugin validate plugins/cache-keeper && claude plugin test plugins/cache-keeper
```

## Удаление

```bash
rm ~/.local/bin/cache-segment.sh
```

Убери `CLAUDE_CODE_PLUGIN_DIRS` и строку состояния из `settings.json` и
перезапусти сессии. После этого можно удалить `~/.local/share/claude-cache-keeper/`.

Переход со старой раскладки: если стоит таймер, убери его
(`systemctl --user disable --now agents-compact-idle.timer cache-keeper-idle.timer`,
затем файлы юнитов из `~/.config/systemd/user/` и `~/.local/bin/cache-keeper-idle`),
запусти `install.sh`; если пользуешься `agents` или другими модами — поставь
`claude-agents-kit`.
